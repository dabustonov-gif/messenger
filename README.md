# Защищённый мессенджер на своём сервере

Android-приложение (Google Pixel 10) + сервер-ретранслятор, который вы держите у себя.
Личные чаты, группы, файлы и фото. Сквозное шифрование: сервер хранит и пересылает только шифротекст.

```
messenger/
├── server/     Python (Starlette + uvicorn), SQLite, Docker + Caddy (TLS)
│   └── gis/    карты: СК-42 ↔ WGS-84, сетка, KMZ для Garmin, PDF для печати (GDAL)
├── android/    Kotlin + Jetpack Compose, libsodium, SQLCipher
└── .github/    облачная сборка APK (GitHub Actions)
```

## Что защищено и от кого

| Угроза | Защита |
|---|---|
| Перехват трафика в сети | TLS; приложение может доверять **только** сертификату вашего сервера (`assets/server_ca.crt`) |
| Кто-то прочитал диск сервера | Там лишь шифротекст и открытые ключи. Сообщения удаляются сразу после доставки, недоставленные — через 30 дней |
| Сервер (или взломщик сервера) подменил ключ собеседника | Ключи закрепляются при первом контакте; смена ключей блокирует отправку, пока вы не сверите 60-значный код безопасности лично |
| Подмена или склейка сообщений | AEAD (AES-256-GCM); ключ сообщения привязан к хэшу тела; номер группы внутри шифротекста сверяется с конвертом |
| Кража / доступ к телефону | Ключи зашифрованы ключом из Android Keystore (StrongBox / Titan M2), база — SQLCipher, бэкапы запрещены, скриншоты запрещены (FLAG_SECURE), в уведомлениях нет текста |
| Регистрация посторонних | Только по одноразовым инвайтам; вход — подписью Ed25519, паролей нет |

**Что сервер всё же видит (метаданные):** кто кому и когда пишет, размер сообщений, названия и состав групп, список пользователей. Это ограничение любой схемы с центральным сервером.

**Чего пока нет (честно):**
- *Forward secrecy.* Ключи сообщений одноразовые, но они «заворачиваются» статичными ключами устройств. Если украдут ключ с телефона, вместе с перехваченным трафиком можно расшифровать прошлую переписку. Следующий шаг — Double Ratchet (libsignal).
- *Несколько устройств на аккаунт.* Один аккаунт — один телефон. При переустановке приложения регистрируйтесь заново, а собеседники увидят предупреждение о смене ключей.
- *Независимый аудит.* Криптография собрана из проверенных примитивов libsodium, но сам протокол никто посторонний не проверял.

## Протокол (v2)

- **Личность:** Ed25519 (подпись) + X25519 (обмен ключами). Ключ X25519 подписан ключом Ed25519, поэтому сервер не может подменить только его.
- **Сообщение:** случайный `msgKey` → `body = nonce‖AES-256-GCM(msgKey, json)`.
  Для каждого получателя: `wk = SHA-256("msgr-wrap-v2"‖X25519(я, он)‖salt‖pk_отпр‖pk_получ)`, `key = salt‖nonce‖AEAD(wk, msgKey, ad=SHA-256(body))`.
- **Группа:** то же тело, ключ заворачивается для каждого участника (до 256). Сервер отклоняет отправку, если список получателей не совпадает с текущим составом группы, поэтому исключённый участник новых сообщений не получит.
- **Файл:** шифруется на телефоне своим ключом, на сервер загружается шифротекст, ключ уходит внутри зашифрованного сообщения.
- **Вход:** сервер выдаёт случайный nonce, телефон подписывает его, в ответ приходит токен на 30 дней.

Эталонная реализация — `server/tests/refclient.py`, побайтно совпадает с `android/.../crypto/E2E.kt`.

## Запуск сервера

Нужен компьютер, который всегда включён: мини-ПК, NAS, Raspberry Pi 4/5 или старый ноутбук с Docker. Для 50+ человек SQLite хватает с запасом.

```bash
cd server
# 1. Впишите в Caddyfile адрес сервера (вместо 192.168.1.50)
docker compose up -d --build

# 2. Первый инвайт (первый зарегистрированный станет администратором)
docker compose exec messenger python manage.py invite
```

Остальные инвайты администратор создаёт прямо в приложении (меню → «Создать инвайт») или командой `python manage.py invite 20`.
Другие команды: `users`, `revoke <имя>` (разлогинить), `delete <имя>`.

### Как подключаться: два варианта (выбор за вами)

**А. Только домашняя/офисная сеть.** Самый закрытый вариант: сервер не виден из интернета, но и сообщения ходят только внутри Wi-Fi.
1. В Caddyfile — локальный IP сервера (закрепите его в роутере).
2. После первого запуска скопируйте корневой сертификат:
   `server/caddy_data/caddy/pki/authorities/local/root.crt` → `android/app/src/main/assets/server_ca.crt`.
3. В приложении укажите адрес `https://192.168.1.50`.

**Б. Доступ отовсюду через Tailscale (рекомендую).** Порты на роутере открывать не нужно, трафик дополнительно идёт внутри WireGuard.
1. Установите Tailscale на сервер и телефоны всех участников, добавьте их в один tailnet.
2. В Caddyfile укажите имя `сервер.ваш-tailnet.ts.net` вместо IP и уберите `tls internal` с `local_certs`. Caddy сам получит настоящий сертификат через Tailscale, тогда `server_ca.crt` не нужен.
3. Для 50+ человек подойдёт бесплатный тариф Tailscale или полностью свой координатор **Headscale**.

Открывать порт 443 напрямую в интернет можно, но так сервер станет мишенью для сканеров. Если всё же решите, поставьте fail2ban и следите за обновлениями.

## Сборка приложения

### Вариант 1: в облаке, без Android Studio (проще всего)
1. Зарегистрируйтесь на github.com и создайте **приватный** репозиторий.
2. Загрузите туда содержимое этой папки (кнопка «uploading an existing file» или `git push`).
   Если используете вариант А с сертификатом, сначала положите `server_ca.crt` в `android/app/src/main/assets/`.
3. Откройте вкладку **Actions**. Сборка «Build APK» запустится сама (~5–10 минут).
4. В завершённом запуске внизу, в разделе **Artifacts**, скачайте `messenger-apk` (zip с `app-debug.apk`).
5. Перешлите APK на телефон, откройте его и разрешите установку из этого источника.

Это отладочная (debug) сборка: для себя и тестов её достаточно. Для раздачи большому числу людей
лучше подписанная release-сборка (вариант 2), чтобы обновления ставились поверх.

### Вариант 2: Android Studio

1. Установите Android Studio (Ladybug или новее) и откройте папку `android/`.
2. Если используете вариант А — положите `server_ca.crt` в `app/src/main/assets/`.
3. На Pixel 10 включите режим разработчика и отладку по USB, затем Run ▶.
   Для раздачи остальным: Build → Generate Signed App Bundle/APK. Создайте свой ключ подписи и замените `signingConfig` в `app/build.gradle.kts`.
4. На телефоне при первом запуске:
   - разрешите уведомления;
   - Настройки → Приложения → Мессенджер → Батарея → **«Без ограничений»**. Без Google-пушей приложение держит соединение с вашим сервером само, и без этого пункта Android будет его усыплять.

## Карты на сервере (модуль gis)

Серверный модуль собирает карту по области и отдаёт файл через API (`/api/maps/...`):
- спутниковые снимки и/или листы Генштаба из ваших GeoTIFF с регулируемой прозрачностью;
- километровая сетка СК-42 (Гаусс–Крюгер), пересчёт датума по ГОСТ Р 51794 (точность ≈ 3 м);
- **KMZ для Garmin Custom Maps**: тайлы JPEG ≤ 1024×1024, лимит тайлов настраивается (по умолчанию 100);
- **PDF** в точном масштабе (1:25 000, 1:50 000…), A4/A3, с автоматической разбивкой на листы.

Данные готовятся заранее, пока есть интернет: `python -m gis.preload --help`.
Для карт нужен GDAL (`sudo apt install gdal-bin python3-gdal`; в Docker-образе он уже есть).
Без GDAL мессенджер работает как обычно, а карты отключаются.

В приложении окна карты пока нет: модуль доступен через API сервера, интерфейс в Android не доделан.
Поддержка Custom Maps есть не на всех часах Garmin (у Instinct карт нет вообще). Проверьте, есть ли
на вашем устройстве папка `Garmin/CustomMaps`.

## Проверка

```bash
cd server
pip install -r requirements.txt pytest
pytest tests
```

19 тестов:
- мессенджер (8): регистрация и инвайты, вход, доставка онлайн/офлайн, подмена, группы, файлы, права, API карт;
- СК-42 (5): ряды Крюгера сверены с полиномами ГОСТ, преобразование Гельмерта — с формулами Молоденского из ГОСТ;
- карты (6): совпадение сетки с расчётом, лимиты Garmin, точный масштаб PDF, разбивка на листы.
